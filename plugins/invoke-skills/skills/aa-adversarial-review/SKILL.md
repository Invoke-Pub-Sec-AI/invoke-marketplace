# AA adversarial review

Try to falsify the candidate or plan within the user's authorized scope. Preserve concise observations, evidence and decisions; do not request private chain-of-thought. A critique assesses support and workflow readiness, not independent accuracy certification or permission to export.

## Select the review surface

- **Research candidate:** inspect bounded windows from the reviewed source snapshot independently of the researcher's selected excerpts. Track which exact windows you inspected. Test material claims against alternatives, counterexamples and missing definitions.
- **Orchestration plan:** use host-provided opaque handles, population counts, registered tasks and safe progress receipts. Judge delegation, required reviews, coverage accounting and terminal states. Source-content validation belongs to document review; a plan reviewer has no reason to request raw documents, private identity/history maps or arbitrary paths.

## Challenge the claims

For metadata, distinguish declared structure from inferred types/meaning. Check record grain, units, key uniqueness, formula interpretation, period coverage, system roles and gaps. A column label, sample value, file location or repeated pattern is insufficient to establish stronger semantics. Require unknown properties to remain explicit rather than becoming invented definitions.

Check the population and denominators: admitted versus skipped/reserved/unread sources, unique inspected coverage, declared counterexample checks, withheld nodes and lost eligible detail. Citation reachability does not establish semantic entailment. Compare each retained claim and relationship to its meaning and evidence; generalized cleanup must preserve factual fidelity. Supplied return history establishes an unverified association, never fulfillment or model-inferred matching.

For plans, require actual registered assignments and the necessary extraction/adversarial/PII/CUI/audit work before acceptance. In the legacy worker, preserve configured leaf budgets across revisions and continuation; parent teams may use separate limits. Preserve task identity and consumed turns across revisions/resume. Terminal withholding, exhaustion or uncertain delivery cannot be bypassed by renaming or re-delegating work. A truthful terminal partial finish is possible when every source is accounted for and no retryable work remains; blocked work stays unaccepted with counts and limitations disclosed.

## Keep durable objections

Use the existing host objection ledger when supplied. The host allocates authoritative opaque objection and task identifiers and validates machine receipts. Without a ledger, label suggested objection IDs as provisional manual annotations, not validated state; retain them across revisions. Each objection states the affected claim/task, failure or uncertainty, inspected evidence and a concrete check or correction. Keep source-bearing citations in the approved target.

For each prior open objection, require an explicit **revised**, **rejected** or **retained_limitation** disposition with concise rationale. Candidate critique uses source evidence you independently inspected; plan critique uses validated host receipts and the actual changed proposal. A retained limitation must appear in the candidate; a rejected objection needs support for rejecting it. An empty later issue list does not resolve earlier objections. Distinguish new evidence from repeated assertions, and leave unresolved obligations open.

Return the current caller's schema with one disposition:

- **pass:** no material open objections and the supplied evidence/receipts support the requested scope.
- **revise:** specific correctable issues remain; identify the required change or discriminating check.
- **withhold:** a terminal safeguard is bypassed or no safely supported result can be established within the assignment.

Report inspected scope, verdict, remaining objections and limitations. Use existing task authorization for local review; this skill does not grant external writes or export. Model review cannot replace the separately authorized exact-byte summary release decision or its no-PII/no-CUI declarations. Source text/IDs, transcripts, critiques, identity maps and lookup originals remain target-only.
