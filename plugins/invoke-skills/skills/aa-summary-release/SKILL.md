# AA summary release

Produce or validate the requested summary artifact through the worker's existing
release path. Read [the target workflow](references/target-workflow.md) before
using an AA draft, archive or CLI; it explains repository discovery and the current
contract checkpoints.

## Check the worker version

Use the parser, settings, and artifact contracts from the exact legacy revision selected for the task. Read `main.py` and `src/cli.py` as source before running commands. The newer PDF launcher starts processing when invoked, even for interface discovery. See [AA project](../aa-project/SKILL.md) for that worker.

## Bind release to the reviewed graph

Use only the validated summary graph: PBC/KSD summaries, system roles, metadata,
links, summary and limitations. Preserve uncertainty and research-proposal status.
All collections, reports and individual PBC/KSD files must derive from that same
graph. A recalculated archive hash cannot authorize a changed graph or divergent
projection.

Keep source files/names, private identifiers, original aliases, lookup maps,
source-bound findings, evidence quotes, paths, traces, critiques and run/workspace
records in the approved target workspace. Only the strict return-contract JSON files enter the
outgoing data ZIP. Target-readable Markdown and `REPORT.txt` stay outside it.
Stable opaque keys may appear in reviewed prose; they do not establish that its
remaining meaning or combinations are releasable.

Local analysis uses fictional or explicitly releasable material. Perform
private candidate, original-value and lookup checks inside the approved target
through its configured worker; filesystem availability alone does not permit
loading private inputs/maps into local Codex. Continue authorized code work,
synthetic validation and operations on eligible reviewed artifacts within scope.

## Review, package and verify

Prepare all outbound projections before exact-byte review. Validate the full
draft and any existing receipt using current worker code. A valid receipt binds
explicit no-CUI, no-PII and return-permission declarations to the exact canonical
release bytes; hashes and model critique do not establish reviewer authority or
content eligibility.

Carry forward applicable explicit authorization already provided by the human.
When the user has reviewed and authorized those exact bytes, record the declared
review and complete the requested local pack/validation without asking again.
When authorization is absent, finish the concrete reviewable draft and identify
the specific missing declaration; never supply review declarations on the
agent's own judgment. Changes require review of the new bytes.

Create archives and unpack into fresh target filesystem locations, preserving
existing files. Validate the complete archive through `read_archive` or the CLI
unpack path, including expected payload identity when supplied. Unpacking stages
inert files and does not apply findings. Report validated artifact identity,
locations and remaining limitations without exposing private contents. Packing
does not authorize a separate transfer or publication outside the target.
